# ChatLuna Meme Generator

ChatLuna v2 的 meme-generator（Python）插件。由 [koishi-plugin-chatluna-meme-generator](https://github.com/Sor85/AAAAACAT-chatluna-plugins/tree/main/plugins/chatluna-meme-generator) **0.0.34** 迁移，保留模板生成、随机去重、头像与文字补全、列表图片、搜索、别名触发及分群排除功能。

配置直接显示在 ChatLuna v2 的插件设置页，使用宿主 **ui-kit / SchemaForm**，保留八组设置；不加载旧 Koishi Console、Vue 浮动导航或另建重复的配置页面。

随机类别权重与文案来源权重使用紧凑表格，每行包含类别／来源、启用、权重及上下移、删除操作。支持新增、空数组与整组恢复默认；配置格式和保存方式不变。表格扩展仅作用于本插件的专属字段角色，无 WebUI 时不影响平台命令。

## 本地开发安装

`@chatluna/*` 当前通过 v2 workspace 提供。本目录只维护源码，不安装依赖、不生成锁文件。开发副本位于 v2 的 `external/meme-generator`。

```sh
# 在插件源码目录同步一次
node scripts/sync-to-v2.mjs --once

# 在 ChatLuna v2 根目录安装 workspace 依赖并构建
yarn install
yarn yakumo build meme-generator
```

同步脚本默认定位 `../../chatluna-v2-mirror`，可通过 `CHATLUNA_V2_ROOT` 指定宿主目录。不带 `--once` 时持续监听源码。同步保留副本的依赖、构建产物和数据目录。

在宿主 `chatluna.yml` 的 `extensions` 分组 `config` 中添加以下条目，或通过宿主插件管理加载：

```yaml
- id: meme-generator
  name: chatluna-plugin-meme-generator
  config:
    baseUrl: http://127.0.0.1:2233
    enableMemeXmlTool: true
```

`baseUrl` 指向 **Agent/ChatLuna 运行机器可访问的** meme-generator Python HTTP 服务；示例不是附带的服务。默认地址为空，需配置后使用。插件不安装、启动或管理 Python 后端，也不会自动修改宿主配置。

更新副本和构建后完整重启宿主 launcher 与 worker，再进行运行验证。源插件不受迁移操作影响。

## 平台命令

| 命令 | 功能 |
| --- | --- |
| `meme <key 或别名> [文字…]` | 生成表情图片 |
| `meme.list` | 按类别显示模板列表，默认输出单张长图 |
| `meme.info <key 或别名>` | 显示别名、图片/文字数量范围和默认文案 |
| `meme.preview <key 或别名>` | 获取模板预览图片 |
| `meme.search <关键词>` | 搜索 key、别名、标签和快捷名称，最多显示 30 条 |
| `meme.random [文字…]` | 按输入条件、类别权重及时间窗口去重选择模板 |

命令使用 v2 内置的 Koishi 命令桥和 Satori 平台会话，遵循宿主命令前缀、权限及路由模式；不是另一个 Koishi 实例。

- 默认允许非纯 ASCII 别名和纯模板 key 无前缀触发，两项可分别关闭；贴合参数、前置 `@` 默认关闭，分别由独立开关控制。已显式保存的关闭值不随默认值变化而覆盖。
- `enableMemeCommandTrigger` 只控制主生成命令，关闭后保留子命令和独立别名功能。
- 当前消息图片在前，引用图片在后；引用图片默认开启，引用文字默认关闭。只有没有显式文字参数时才采用引用文字。
- 后端返回的 shortcut 参数与旧版一致，仅用于别名检索，不自动作为生成 args 执行。

## 自动补全与随机选择

**文案补全**：默认文字和发送者昵称各占 100 权重；选中的来源不可用时按配置顺序尝试其他有效来源。昵称补全仅适用于最少文字数不超过 1 的模板。完全没有默认文案时，群昵称可作为最终回退，优先被提及用户，其次发送者。已有文字不足最少数量时仅追加缺额；不覆盖已有足量文字。

**头像补全**：保留发送者、被提及用户和机器人头像的原有优先级。仅一张图片缺口时可追加发送者头像；无图的单图/双图模板根据提及顺序补齐。头像缺失时会回查群成员和用户信息，失败时跳过该头像。

**随机选择**：先按类别权重选桶，再在桶内均匀选择；五类默认全部启用、权重均为 100。随机生成强制启用头像补全，不受普通生成的三个头像开关关闭影响。

- 默认在 24 小时内去重；历史仅在插件实例内存中，跨群、跨用户共享，重启后清空。
- 开启去重时随机调用串行执行，只有成功生成才记入历史。
- 当前输入的候选全部耗尽时，仅这组候选允许重新轮回，不清空其他模板历史。
- 生成失败会尝试其他候选；所有权重为零或禁用时不会退回无权重随机。
- `randomOutputMemeKey` 用于复现单模板问题，绕过普通候选和排除筛选，但仍需满足输入与随机桶条件。

## 原生工具与 XML 动作

`enableMemeXmlTool` 默认关闭。开启后注册 v2 原生 **`meme_generate`** 工具以及映射到同一个工具的 **`meme`** 动作，由宿主统一处理工具权限与动作执行。

```xml
<meme key="hug" at="发送者ID|机器人ID"/>
<meme key="字幕模板" text="第一段|第二段"/>
```

原生工具参数示例：

```json
{
  "key": "hug",
  "at": ["发送者ID", "机器人ID"]
}
```

批量生成按 `actions` 顺序执行：

```json
{
  "actions": [
    { "key": "模板一", "text": ["第一段", "第二段"] },
    { "key": "模板二", "image": "i123abc" }
  ]
}
```

- `text`、`image`、`at` 支持字符串或字符串数组；字符串以 `|` 拆分，数组项内部的 `|` 保留。也兼容 `texts`、`images`、`ats`。
- `image` 支持当前 agent 会话中的图片 ref 和公网 HTTP(S) 图片地址；取原图，不取缩略预览。不接受任意本地文件路径或其他会话的图片引用。
- 工具只消费显式参数，不自动继承触发消息的图片、文字或 `@`；缺省内容仍使用相同补全策略。
- 成功时图片已经发送到当前平台会话，同时以 v2 结构化图片结果返回模型，不需要重复发送。
- 必须绑定平台会话；未绑定、模板被排除或后端失败时返回工具错误，不伪造成功。
- 旧 `injectMemeXmlToolAsReplyTool` 键保留但隐藏，v2 不再注入 `character_reply` 参数；两种旧 AI 接入方式统一到原生工具/动作。不再包装 `getTemp` 或监听 `completionMessages.push`。
- `memeXmlReferencePrompt` 保留为管理员参考文本，不自动注入，也不自动替换 `{bot_id}`。v2 动作由原生渲染管线识别，不保留旧正则对不规范 XML（例如缺少等号）的容错。

## 列表、排除与错误处理

- 分类顺序：无需参数、仅文字、仅图片、图片和文字、信息获取失败。模板信息失败时仍显示 key。
- 列表图片使用 Takumi，带中韩文字体，1200 CSS 像素布局、2 倍输出密度。`single` 为一张长图，`multiple` 按 1600 CSS 像素高度整行分页。
- 文本列表按 UTF-8 3000 字节拆分。OneBot 支持列表/搜索合并转发，专用转发失败后尝试通用接口，再回退普通消息；单张列表图片直接发送。
- 全局 key、模板类别和当前群的排除规则取并集。分类排除中的“双图”包括最少图片数大于 2 的模板；随机桶的“双图”只包含恰好 2 图，两者有意不同。
- 平台错误默认仅写日志，搜索无结果仍显示提示。原生工具错误始终交给模型，避免静默失败被当作成功。

## 网络与数据

- 后端请求使用宿主 HTTP 服务配置；管理员可将后端部署在内网。
- 网络图片只允许公网 HTTP(S)，逐跳校验重定向和 DNS 地址，并将连接固定到已校验地址，单图流读取上限为 10 MiB。平台提供的 PNG/JPEG/GIF/WebP 内联图片同样支持，解码前后都检查大小，不允许任意本地路径或 SVG 数据。
- 后端生成和预览图片上限为 50 MiB，防止异常响应无限占用内存。
- 插件不新增数据库，不保存生成历史或将图片落盘；随机历史和列表渲染缓存均为内存状态。
- 不附带任何凭据，不主动向真实平台发送测试消息。

