# ChatLuna Meme Generator

为 ChatLuna v2 提供表情包生成、模板搜索与预览、随机去重、头像和文案补全，支持命令、别名触发及模型调用。

插件连接独立的 **meme-generator（Python）HTTP 服务**，可按模板 key、类别和群组限制可用模板。

## 开始使用

1. 准备 meme-generator Python HTTP 服务，确认 ChatLuna 所在机器可以访问。
2. 在 ChatLuna v2 中启用本插件，将「后端地址」`baseUrl` 设置为该服务的地址。
3. 使用 `meme.list` 查看模板，通过 `meme.search <关键词>` 查找所需表情。

`baseUrl` 默认留空，配置后才能使用。后端可以部署在内网；插件不附带、安装或启动 Python 服务。

模型调用需要额外开启「原生动作与工具」`enableMemeXmlTool`，默认关闭，详见[模型调用](#模型调用)。

## 平台命令

| 命令 | 功能 |
| --- | --- |
| `meme <key 或别名> [文字…]` | 生成表情图片 |
| `meme.list` | 按类别显示模板列表，默认输出单张长图 |
| `meme.info <key 或别名>` | 查看别名、图片／文字数量要求和默认文案 |
| `meme.preview <key 或别名>` | 获取模板预览图片 |
| `meme.search <关键词>` | 搜索 key、别名、标签和快捷名称，最多显示 30 条 |
| `meme.random [文字…]` | 按输入条件和类别权重随机生成，支持时间窗口去重 |

命令遵循 ChatLuna 的命令前缀、权限及路由设置。

### 触发与输入

- 默认允许非纯 ASCII 别名和模板 key 无前缀触发，两项可分别关闭。贴合参数、前置 `@` 触发默认关闭，可分别开启。
- `enableMemeCommandTrigger` 只控制主生成命令，关闭后仍保留子命令和独立别名触发。
- 图片可放在命令前后。生成时优先使用当前消息图片，再使用引用消息图片；引用图片默认开启。
- 引用文字默认关闭；开启后，仅在没有显式文字参数时采用引用文字。
- 模板快捷名称用于检索，不会自动作为生成参数执行。

## 自动补全与随机选择

### 文案与头像补全

- **文案**：默认文案与发送者昵称的初始权重均为 100。选中的来源不可用时，按配置顺序尝试其他有效来源；已有文字不足时按段位补齐缺额（如只填了首段，从第二段默认文案开始补），不覆盖足量文字。
- **昵称**：单段模板直接以昵称作为文案；多段模板（如奖状）以昵称替换首段，其余段沿用默认文案，默认文案不足以凑满最少段数时不使用昵称。完全没有默认文案的单段模板，群昵称可作为最终回退，优先使用被提及用户，其次发送者。
- **头像**：无图的单图／双图模板按提及顺序及头像补全配置补齐；仅缺一张图片时可追加发送者头像。头像缺失时尝试查询群成员和用户信息，仍不可用则跳过。

### 随机规则

- 先按类别权重选择类别，再在类别内等概率选择模板；五类默认全部启用，权重均为 100。
- 随机生成强制启用头像补全，不受普通生成的三个头像补全开关影响。
- 默认在 **24 小时**内去重，记录在当前插件实例内跨群、跨用户共享，重启后清空。开启去重时，随机调用依次执行，只有成功生成才记入历史。
- 当前输入的候选全部耗尽后，仅这组候选重新轮回，不清空其他模板历史。
- 生成失败时尝试其他候选；所有类别被禁用或权重均为零时，不会退回无权重随机。
- `randomOutputMemeKey` 可固定随机模板，会绕过普通候选和排除筛选，但仍需满足输入与随机类别条件。

## 模型调用

开启 `enableMemeXmlTool` 后，模型通过 **`meme_search` 工具查询模板**，再通过 **`meme` XML 动作生成并发送图片**。查询本身不生成或发送图片，不影响人工命令。

### 查询模板

```json
{
  "keywords": ["安慰", "抱抱"],
  "limit": 5
}
```

- `keywords` 支持字符串或 1–8 项字符串数组，每项最多 200 字符；多个关键词的结果合并去重，字符串中的 `|` 不作为分隔符。
- `limit` 默认 5，最多 10。结果包含模板 key、关键词、别名、标签、图片／文字数量要求和默认文案，并遵守全局、当前群及类别排除规则。
- 检索覆盖 key、关键词、别名、标签和默认文案，忽略全半角与字母大小写差异，精确匹配优先。无匹配时返回空列表，应调整查询，不猜测模板 key。
- 模板索引默认缓存 30 分钟，可通过 `memeSearchCacheMinutes` 调整，重启后清空。`failed_templates` 大于零表示部分模板资料读取失败，结果可能不完整；全部读取失败时返回错误。

### 生成与发送

模板 key 和参数要求以查询结果为准，动作格式如下：

```xml
<meme key="模板key" text="文字内容" at="用户ID"/>
```

| 参数 | 说明 |
| --- | --- |
| `key` | 查询得到的模板 key，必填 |
| `text` | 文字内容，多项用 `\|` 分隔 |
| `at` | 用于头像和昵称补全的用户 ID，多项用 `\|` 分隔 |
| `image` | 当前活动会话的图片 ref 或公网 HTTP(S) URL，多项用 `\|` 分隔 |

`text`、`at`、`image` 也兼容复数形式 `texts`、`ats`、`images`。动作只使用显式参数，不自动继承触发消息中的图片、文字或提及；缺省内容按头像与文案补全配置处理。

查询和动作均需要平台会话。图片 ref 仅限当前活动会话，不能引用其他会话或任意本地路径。非法参数、模板被排除或生成失败时，错误交由 ChatLuna 反馈给模型。

### 并发与排队

同一平台会话的动作依次执行，不同会话可并发。每个成功动作只发送一次图片，无需模型重复发送。

| 配置 | 默认值 | 范围与作用 |
| --- | --- | --- |
| `memeActionConcurrency` | 4 | 跨会话动作并发上限，1–16 |
| `memeActionQueueTimeoutSeconds` | 30 秒 | 排队等待时限，1–300 秒 |
| `memeActionQueueLimit` | 5 | 每会话等待数量上限，1–20，不含执行中的动作 |

单个插件实例最多等待 100 条动作。排队超时或超限时明确失败，不自动重试或延迟补发。生成超时从实际开始执行后计算，不包含排队时间；上述限制不改变普通聊天、人工命令和随机去重的并发策略。

## 列表与模板排除

- 模板按「无需参数、仅文字、仅图片、图片和文字、信息获取失败」分类；信息读取失败时仍显示 key。
- 列表支持图片和文本输出。图片模式 `single` 输出长图，`multiple` 分页输出；文本过长时自动拆分。
- OneBot 支持列表／搜索结果合并转发，失败时回退为普通消息；单张列表图片直接发送。
- 全局 key、模板类别和当前群的排除规则共同生效。分类排除中的「双图」也包含最少需要三张及以上图片的模板；随机类别中的「双图」仅包含恰好需要两张图片的模板。
- 平台命令错误默认仅写日志，搜索无结果仍显示提示；模型调用错误始终反馈给模型。

## 网络与数据限制

- 外部图片地址只允许公网 HTTP(S)，会校验 DNS 和重定向，单张图片上限为 **10 MiB**。平台内联图片支持 PNG、JPEG、GIF、WebP，同样受此大小限制；不接受任意本地路径或 SVG 数据。
- 后端生成和预览图片上限为 **50 MiB**。
- 插件不新增数据库，不将生成图片落盘。随机历史、模板索引和列表渲染缓存仅保存在内存中。
